Start Here

Do these first. They reduce the most launch risk.

Real two-account isolation

Verify account B never sees or overwrites account A data after switching accounts in the same browser session.

Critical Data safety gate Needs two real accounts
  1. Use production and sign into account A.
  2. Create or identify a clearly named project in account A and add a unique sentence to a scene.
  3. Sign out, then sign into account B without restarting the browser.
  4. Confirm account B does not show account A projects, scenes, theme, AI settings, or storage state.
  5. Create or edit one small account B project, refresh, and confirm it persists.
  6. Sign back into account A and confirm account A still has its project and unique sentence.

Two-tab overwrite and warning check

Verify two open tabs on the same account do not silently lose edits, and same-scene editing warns proactively.

Critical Data safety gate Production browser
  1. Open the same signed-in account in two browser tabs.
  2. Edit different records, such as one character in tab 1 and one location in tab 2; refresh both and confirm both survive.
  3. Edit different fields on the same record in two tabs; refresh both and confirm both fields survive.
  4. Open the same scene in both tabs; confirm the second tab shows an "also open" warning before editing.
  5. Choose "Edit anyway", make distinct scene edits, wait for "Saved", refresh both tabs, and confirm no edit silently disappears.

Fresh account sample and first-project flow

Check a genuinely new account sees the correct first-run choices, sample project behavior, and AI setup prompt.

High Auth Onboarding
  1. Create a new account in a clean browser profile or private window.
  2. Choose the sample tour; confirm exactly one editable Sample Project opens with linked writing/worldbuilding content.
  3. Confirm the AI setup prompt appears before any product tour.
  4. Delete the sample, refresh and re-login, and confirm the sample is not recreated.
  5. Create a second fresh account, choose "Start my own project", and confirm the AI setup prompt appears after the first project is created.

AI key sync and isolation

Confirm synced AI provider keys follow only the intended account and are never visible in another account or logs.

Critical Security Needs provider key
  1. In account A, save an AI provider key with sync enabled.
  2. Open account A in a clean browser profile and confirm AI settings/tools can use the synced provider without re-entry.
  3. Sign into account B in the original browser and confirm account B cannot see or use account A's key/settings.
  4. Disable sync in account A, save, then open account A in a clean profile and confirm the key no longer follows the account.
  5. Use browser network/devtools while making one AI request and confirm the key is not visible in URLs, responses, console logs, or analytics.

Free plan map, AI lock, and storage cap

Confirm Free users get the promised 250 MB cloud storage, Map Builder access, and AI lock behavior.

High Legal promise Free account
  1. Use a real Free account with one active project.
  2. Open Map Builder on desktop or tablet, draw one object, refresh, and confirm it persists.
  3. Open AI Tools and confirm it shows the upgrade/access wall rather than attempting a request.
  4. Confirm account storage UI says 250 MB for Free.
  5. Confirm a Monthly or beta tester account shows the current higher quota, not the old 5 GB value.

Live media upload and cleanup

Verify real Supabase Storage writes, quota updates, replacement cleanup, and delete cleanup.

High Storage Real account
  1. Upload a small image as a project cover or character portrait in a real signed-in account.
  2. Refresh and confirm the image remains visible.
  3. Replace it with a second image, then confirm the old object is removed from Storage if you have Supabase access.
  4. Delete the record or remove the image and confirm the current object is cleaned up.
  5. Confirm storage-used numbers increase/decrease reasonably.

Project delete cleans scene rows

Delete a throwaway project and confirm no orphan scene rows remain for that project id.

High Supabase check Destructive QA
  1. Create a throwaway project and add two scenes with unique text.
  2. Record the project id if available.

  4. Query Supabase scenes for that project id and confirm zero rows remain.

Desktop And Local Mode

Only run these when the desktop build is ready to test.

Desktop account-only surface

Desktop should show account settings and device management, not the full web workspace.

High Desktop Entitlement
  1. Launch desktop signed out and confirm the compact login/auth screen appears.
  2. Sign in with Free, Monthly, Lifetime, and Founder accounts as available.
  3. Confirm every plan lands in Account Settings only, with no project library/editor or marketing pages.
  4. For entitled accounts, verify Membership shows desktop device information.
  5. Test sign-out and, if possible, device cap/deactivation behavior.

Desktop vault, Local-first, and sync status

Verify local vault relocation, local persistence, cloud-sync paused states, and recovery messaging.

High Desktop Local Mode
  1. Move the vault to an empty folder and confirm projects/backups remain after reload.
  2. Cancel the folder picker and confirm nothing changes.
  3. Enable Local-first, edit writing and worldbuilding records, quit/reopen, and confirm changes remain.
  4. Confirm automatic cloud sync is paused while Local-first is on.
  5. Force a sync failure and confirm the UI shows retryable error messaging without blocking editing.

Promise And Final Switch

Run after the core safety checks, with checkout still parked until last.

Pricing page and beta-interest flow

Confirm public prices are correct and beta-interest captures signed-in and signed-out users without enabling checkout.

Medium Beta-interest stays Payment promise
  1. Hard refresh production Pricing and FAQ.
  2. Confirm Monthly GBP10, Lifetime GBP99, Founder GBP299, and hosting renewal GBP6/year copy.
  3. Click each paid CTA and confirm the beta-interest modal opens, not Stripe Checkout.
  4. Submit once signed in and confirm email plus beta_tester metadata if you have dashboard access.
  5. Submit once signed out and confirm it records interest without granting account access.

Marketing truth pass

Confirm public pages do not promise excluded launch features or overstate D&D/TTRPG use cases.

Medium Marketing gate Copy review
  1. Review Home, Features, FAQ, Pricing, About, AI Overview, and feature landing pages.
  2. Flag any wording that implies collaboration, public sharing, player portals, mobile apps, marketplace/community, publishing integrations, advanced fantasy calendars, or live VTT play.
  3. Confirm D&D/TTRPG copy reads as private GM prep and campaign planning.
  4. Check pages at desktop, tablet, and phone widths for obvious broken layout.

Final checkout switch

This stays last: remove/migrate beta-interest and re-enable real checkout only when every other gate is ready.

Critical Do last Payment gate
  1. Confirm every other launch gate is passed or explicitly deferred by product decision.
  2. Decide how to handle beta_tester accounts: migrate, expire, or keep manually entitled.
  3. Re-enable paid checkout CTAs.
  4. Verify live Stripe products, prices, webhooks, success URLs, cancel URLs, portal URLs, and metadata updates.
  5. Run success, cancel, failed-payment, cancellation, and downgrade checks.
How to use this tracker

Progress is stored in this browser's localStorage. Use Export JSON after each QA session if you want a portable backup or want to share notes back into the repo. This file is intentionally smaller than the full QA plan: it only tracks tasks that require a human, live accounts, dashboards, devices, or judgement.
