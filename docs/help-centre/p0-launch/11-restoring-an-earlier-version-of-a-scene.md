# Restoring an earlier version of a scene

Scene version history lets you preview earlier saved text and restore it when a revision did not work out.

## The how

1. Open the manuscript and select the scene.
2. Select the scene’s **Version history** control, or open **More → Version history**.
3. Select a saved version to preview it.
4. Check its date, word count and text.
5. Select **Restore this version**.
6. If you restored the wrong version, use the offered **Undo** action while it remains available.

📸 SCREENSHOT: Open **Version history** for a disposable scene with at least three meaningfully different versions. Show the version list, one expanded preview and **Restore this version**. Crop to the history panel and use fictional text.

### Delete saved versions

- Use the delete control beside one version to remove only that version.
- Use the clear-history control to remove all saved versions for the scene, then confirm the warning.

Deleting version history does not delete the current scene, but removed versions cannot be selected from this history afterwards.

## The why: what restoration changes

Restoring applies the selected version to the current scene immediately. It does not create a second scene or restore the rest of the project. The scene title and supporting records are not rolled back unless they are part of the saved version data shown by the interface.

Version history is different from:

- **Conflict copies**, which preserve competing edits made in separate tabs.
- **Project backups**, which contain a restore-ready copy of a whole project.
- **Retired manuscripts**, which archive the full manuscript structure and start a fresh working manuscript.
- **Desktop vault snapshots**, which restore an entire local vault.

Use scene history for a local prose decision. Use a project backup when several records or structural changes need to be recovered together.
